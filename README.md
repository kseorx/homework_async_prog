# Домашнее задание №4. Асинхронное программирование в Python

Решение задач на понимание разницы между синхронным и асинхронным кодом, а также на правильную обработку I/O и CPU-bound операций с использованием `asyncio` и `httpx`.

## Структура проекта

Каждое задание вынесено в отдельный файл. **В начале каждого файла `task_X.py` находится корректно оформленный docstring с объяснением решения и реальными замерами времени выполнения**, как того требует рубрикатор.

- `task_0.py` — разминка-ловушка «Почему не быстрее?» (исправление последовательного `await` в цикле).
- `task_1.py` — сравнение синхронного (`requests`) и асинхронного (`httpx` + `asyncio.gather`) подходов.
- `task_2.py` — реальный I/O: таймауты, экспоненциальный backoff с jitter и изоляция ошибок.
- `task_3.py` — (*) вынос CPU-bound вычислений из event loop с помощью `ProcessPoolExecutor`.
- `theory.md` — ответы на теоретические мини-кейсы.
- `requirements.txt` — зависимости проекта.

## Краткое содержание решений

### Задание 0. Разминка-ловушка

- **Проблема:** `await` внутри цикла `for` выполняет запросы строго последовательно, поэтому ускорения нет.
- **Решение:** `asyncio.gather` для конкурентного запуска всех задач одновременно.
- **Замеры времени:** указаны в docstring файла `task_0.py`.

### Задание 1. Синхронно vs асинхронно

- **Разница:** синхронный код блокирует поток на время сетевого ожидания (I/O-bound). Асинхронный код использует event loop, который переключается на другие задачи в моменты ожидания, позволяя выполнять запросы конкурентно в рамках одного потока.
- **Замеры времени:** указаны в docstring файла `task_1.py`.

### Задание 2. Реальный I/O и обработка ошибок

- **Реализация:**
  - `timeout=5.0` для каждого запроса;
  - цикл повторных попыток (макс. 3) с экспоненциальной задержкой (`backoff = 2 ** attempt`) и случайным jitter;
  - функция `robust_main` изолирует ошибки, возвращая кортеж `(успешные_результаты, список_ошибок)`, чтобы падение одного URL не роняло всю пачку задач.
- **Замеры времени:** указаны в docstring файла `task_2.py`.

### Задание 3 (*). Вынос CPU-bound вычислений

- **Проблема:** прямой вызов тяжёлой функции `heavy()` (sha256) в корутине блокирует event loop, из-за чего фоновая задача `ticker` замирает.
- **Решение:** вынос вычислений в отдельный процесс через `loop.run_in_executor` и `ProcessPoolExecutor`. Вычисления идут вне GIL основного процесса, и event loop продолжает работать (точки `ticker` бегут непрерывно).
- **Замеры времени:** указаны в docstring файла `task_3.py`.

## Теоретическая часть (мини-кейсы)

Полные ответы также продублированы в файле `theory.md`.

### Парсер, считающий хеши 10 000 файлов

- **Выбор:** процессы (`multiprocessing` / `ProcessPoolExecutor`).
- **Обоснование:** это CPU-bound задача; из-за GIL потоки в Python не могут выполнять байт-код параллельно, поэтому для реального ускорения нужны отдельные процессы.

### Бот, который на каждый запрос обращается к 5 внешним API

- **Выбор:** асинхронность (`asyncio`).
- **Обоснование:** это классическая I/O-bound задача; асинхронность позволяет дёшево и без блокировок держать множество одновременных сетевых соединений в рамках одного потока.

### Скрипт, выгружающий 100 000 строк из БД пачками

- **Выбор:** асинхронность (`asyncio`) или потоки (`asyncio.to_thread`).
- **Обоснование:** это I/O-bound задача (ожидание ответа от БД); асинхронный драйвер или вынос синхронного драйвера в поток позволит не блокировать основное приложение во время чтения чанков данных.
